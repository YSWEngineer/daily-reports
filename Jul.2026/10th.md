### SQL 第2版 ゼロからはじめるデータベース操作
#### データベースとは何か
- データベース：大量の情報を保存し、コンピュータから効率よくアクセスできるように加工したデータの集まりのこと
- DBMS：データベースを管理するコンピュータシステムのこと（データベース管理システム：**D**ata**B**ase **M**anagement **S**ystem）
- データベースは DB（ディービー）と呼ぶ
- DBMS は、ディービーエムエスと呼ぶ
- **データベースと DBMS はよく混同されるが、データの集まりを DB、DB を管理するシステムを DBMS と理解しておく**
- DBMS の利点は、**大量のデータを多人数でも安全かつ簡単に扱えること**
- リレーショナルデータベース（Relational Database：RDB）：「**関係データベース**」とも呼ばれ、列と行からなる2次元表の形式でデータを管理する。また、**SQL**（**S**tructured **Q**uery **L**anguage：構造化問い合わせ言語）という言語を用いてデータを操作する

#### データベースの構成
- データベースを読み書きするには、サーバである RDBMS にクライアントから SQL文を送信する
- リレーショナルデータベースでは、「テーブル」や「表」と呼ばれる2次元表でデータを管理する
- テーブルは、データ項目を表す「列（カラム）」と、1件のデータを表す「行（レコード）」からなる。データの読み書きはレコード単位で行われる
- 列と行を交わる1つのマス目を「セル」と呼ぶ。1つのセルには1つのデータしか入れられない
- サーバ：プログラムからの要求を受け取り、それに応じて処理を行うタイプのプログラム、あるいはそのプログラムがインストールされたマシンのこと
- クライアント：サーバに要求を出すプログラム、あるいはそのプログラムがインストールされたマシンのこと

#### SQLの概要
- SQL はデータベースを操作するために開発された言語
- SQL では、操作したいことを1つの文(SQL文)で記述し、RDBMS に向けて送信する
- 文末には区切りとしてセミコロン（`;`）を付ける
- SQL の Q（Query）は「問い合わせ」や「検索」という意味
- SQL文は、RDBMS に与える命令の種類によって3つに分類される
  - **DDL**（**Data Definition Language**）：**DDL**（**データ定義言語**）は、データベースやデータテーブルなどを作成したり削除したりする。DDL に分類される命令は以下のとおり
    - **CREATE**：データベースやデータテーブルなどを作成する
    - **DROP**：データベースやデータテーブルなどを削除する
    - **ALTER**：データベースやデータテーブルなどの構成を変更する
  - **DML**（**Data Manipulation Language**）：**DML**（**データ操作言語**）は、テーブルの行を検索したり変更したりする。DML に分類される命令は以下のとおり
    - **SELECT**：テーブルから行を検索する
    - **INSERT**：テーブルに新規行を登録する
    - **UPDATE**：テーブルの行を更新する
    - **DELETE**：テーブルの行を削除する
  - **DCL**（**Data Control Language**）：**DCL**（**データ制御言語**）は、データベースに対して行なった変更を確定したり取り消したりする。DCL に分類される命令は以下のとおり
    - **COMMIT**：データベースに対して行なった変更を確定する
    - **ROLLBACK**：データベースに対して行なった変更を取り消す
    - **GRANT**：ユーザに操作の権限を与える
    - **REVOKE**：ユーザから操作の権限を奪う
- SQL では、キーワードの大文字・小文字は区別されない
- SQL文の中にじかに書く文字列や日付、数値などを**定数**と呼ぶ
- SQL における定数の書き方
  - 文字列を SQL文の中に記述する場合は、シングルクォーテーションで囲む
  - 日付も文字列と同様にシングルクォーテーションで囲む
  - 数値の場合は囲まず、数値だけ書く
- 単語の間を半角スペース、または改行で区切る

#### テーブルの作成
- テーブルを作成するには、その前にテーブルを格納するためのデータベースを先に作らなければならない
- RDBMS上にデータベースを作成するには、**CREATE DATABASE文**という SQL文を実行する
```sql
-- データベースを作成するCREATE DATABASE文
CREATE DATABASE <データベース名>;

-- shopデータベースを作成するCREATE DATABASE文
CREATE DATABASE shop;
```
- データベースを作成できたら、次に CREATE TABLE文でテーブルをその中に作成する
```sql
-- テーブルを作成するCREATE TABLE文
(<列名1> <データ型> <この列の制約>,
 <列名2> <データ型> <この列の制約>,
 <列名3> <データ型> <この列の制約>,
 <列名4> <データ型> <この列の制約>,
   .
   .
   .
 <このテーブルの制約1>, <このテーブルの制約2>, ......);
```
- データベスやテーブル、列などの名前に使ってよい文字は、次の3種類
  - 半角のアルファベット
  - 半角の数字
  - アンダーバー
- 名前の最初の文字は「半角のアルファベット」にすること
- 名前は重複してはならない
- データ型はデータの種類を表し、数値型、文字列型、日付型などがあり、どの列もデータ型に反するデータを入れることはできない
- SQL を学ぶには基本的なデータ型4つを覚えておけばよい
  - **INTEGER型**（インテジャーがた）：整数を入れる列に指定するデータ型（数値型）。少数は入れられない
  - **CHAR型**（キャラがた）：CHAR は CHARACTER（文字）の略で、文字列を入れる列に指定するデータ型（文字列型）。`CHAR(10)`や`CHAR(200)`のように、列の中に入れることのできる文字列の長さを`()`で指定する。CHAR型の列には**固定長文字列**という形式で文字列が格納される
    - 固定長文字列：列に入れる文字列の長さが最大長に満たない場合、文字数が最大長になるまで空きを半角スペースで埋める
  - **VARCHAR型**（バーキャラがた）：CHAR型と同じく文字列を入れる列に指定するデータ型（文字列型）で文字列の長さを`()`で指定する。**可変長文字列**という形式で列の中に文字列が入る
    - 可変長文字列：文字数が最大長に満たなくても、半角スペースで埋めたりしない
  - **DATE型**（デイトがた）：日付（年月日）を入れる列に指定するデータ型（日付型）
- **制約**：データ型のほかに、列に入れるデータに制限や条件を追加する機能
- **NULL**（ヌル）：「無記入」状態であることを表すキーワード
- **キー**：特定のデータを指定するときに使う列の組み合わせのこと
- **主キー**（**プライマリーキー**）：1つの行を特定できる列のこと

#### テーブルの削除と変更
- テーブルの削除は DROP TABLE文で書ける
```sql
-- テーブルを削除するDROP TABLE文
DROP TABLE <テーブル名>;
```
- 一度削除したテーブルは復活できない。またテーブルを CREATEして、データを登録し直さなければならない。が、RDBMS の多くが復活させる機能を備えている。
- テーブルの列を追加するには ALTER TABLE文を使う
```sql
-- 列を追加するALTER TABLE文
ALTER TABLE <テーブル名> ADD COLUMN <列の定義>;
```
- テーブルの列を削除するには以下のように書く
```sql
-- 列を削除するALTER TABLE文
ALTER TABLE <テーブル名> DROP COLUMN <列名>;
```
- テーブル定義を変更したら元に戻せない
- **BEGIN TRANSACTION**文：トランザクションを開始する命令文
- **COMMIT**文：行の追加を確定する命令文

#### SELECT文の基本
- テーブルからデータを選択するには SELECT文を使う
```sql
-- 基本的なSELECT文
SELECT <列名>, ......
  FROM <テーブル名>;
```
- SELECT文で必要なデータを検索し、取り出すことを「**問い合わせ**」「**クエリ（query）**」と呼ぶ
- すべての列を出力したいときには、すべての列を意味する**アスタリスク**（`*`）を使う
```sql
-- すべての列を出力
SELECT *
  FROM <テーブル名>;
```
- アスタリスクを使うと、結果の列の並び順を指定することができない
- **ASキーワード**を使い、列に別名をつけることができる
```sql
-- 列に別名をつける
SELECT shohin_id  AS id,
       shohin_mei AS namae,
       shiire_tanka AS tanka
  FROM Shohin;
```
- 別名には日本語を使うこともできる。その場合は、別名を**ダブルクォーテーション**（`"`）で囲む
- 重複行を省きたいときは、SELECT句で**DISTINCT**というキーワードを使う
- SELECT文では、選択したい行の条件を**WHERE句**で指定する
```sql
-- SELECT文のWHERE句
SELECT <列名>, ......
  FROM <テーブル名>
 WHERE <条件式>;
```
- コメントは、SQL文に説明や注意事項などを付記するもの。コメントは SQL の実行には影響を及ぼさない。コメントをつける方法は以下の2つ
  - **1行コメント**：`--`の後に記述する。1行の中でしか書けない
  - **複数行コメント**：`/*`と`*/`で囲った中に記述する。複数行にわたって書ける

#### 算術演算子と比較演算子
- SQL文の中には計算式を書くことができる
- SELECT句には定数も式も書ける
- NULL を含んだ計算は、NULL になる
- NULL である行を選択したいときは、条件式に IS NULL演算子を使う
- NULL でない行を選択したいときには、条件式に IS NOT NULL演算子を使う

#### テーブルを集約して検索する
- テーブルの列の合計値や平均値などの集計操作を行うには集約関数を使う
- 集約関数は基本的に NULL を除外して集計する。ただし、COUNT関数のみ、「COUNT(*)」とすることで NULL を含めた全行を数える
- 重複値を除外して集計するには DISTINCTキーワードを使う
- 集計用の関数を「**集約関数**」「**集合関数**」と呼ぶ
   - **集約**：「複数行を1行にまとめる」という意味

#### テーブルをグループに切り分ける
- 集約関数と GROUP BY句を使うことで、テーブルを切り分けて集約できる
- 集約キーに NULL が含まれる場合は、集計結果にも「不明」行（空行）として現れる
- 集約関数と GROUP BY句を使うときの4つの注意
  - ① SELECT句に書けるものが限定される
  - ② GROUP BY句には SELECT句で付けた列の別名は使えない
  - ③ GROUP BY句は集約結果をソートしない
  - ④ WHERE句に集約関数を書くことはできない

#### 集約した結果に条件を指定する
- 集約関数を書ける場所は SELECT句、HAVING句、ORDER BY句
- HAVING句は GROUP BY句の後ろに書く
- WHERE句には「行に対する条件指定」を書き、HAVING句には「グループに対する条件指定」を書くという使い分けをする

#### 検索結果を並べ替える
- 検索結果の並べ替えに ORDER BY句を使う
- ORDER BY句の列名の後ろに ASCキーワードを付けると昇順、DESCキーワードを付けると降順に並べ替えることができる
  - ASC は ascendent（昇っていく）、DESC は descendent（降っていく）という単語の略
- ORDER BY句は、複数のソートキーを指定することが可能
  - **ソートキー**：ORDER BY句に書く列名を指す
- ソートキーに NULL が含まれていた場合、先頭か末尾にまとめられる
- ORDER BY句では SELECT句でつけた列の別名を使える
- ORDER BY句では SELECT句に含まれていない列や集約関数を使える
- ORDER BY句で列番号を使ってはいけない
- ORDER BY句は常に SELECT文の最後尾に書く

#### データの登録（INSERT文の使い方）
- テーブルにデータ（行）を登録するには INSERT文を使う。INSERT文は1回の実行で1行を挿入するようにする
  - INSERT：挿入すること、差し込むこと
- 列名や値を間まで区切って、外側を括弧`()`で括った形式をリストと呼ぶ
- NULL を挿入するには VALUES句の値リストに「NULL」を書く
- テーブルの列にはデフォルト値（初期値）を設定することができる。デフォルト値を設定するには、CREATE TABLE文の中で、列に対して **DEFAULT制約**をつける
- デフォルト値を挿入するには、INSERT文の VALUES句に DEFAULTキーワードを指定する方法と、列リストを省略する方法の2種類がある
- 別のテーブルからデータをコピーするには INSERT ... SELECT を使う

#### データの削除（DELETE文の使い方）
- テーブルごとすべて削除するには DROP TABLE文を、テーブル自体は残して行のみをすべて削除するには DELETE文を使う
  - DROP TABLE文はテーブルごとすべて削除するため、一度削除した後にデータを再登録するには、CREATE TABLE文でテーブルの作成から始めなければならない
- DELETE文の基本構文
```sql
-- テーブルは残したまま、すべての行を削除するDELETE文
DELETE FROM <テーブル名>;
```
  - DELETE文の場合は、データ（行）を削除してもテーブルは残っているため、INSERT文によってすぐにデータを再登録することが可能
- 一部の行を削除するときは、WHERE句で対象行の条件を書く。WHERE句で削除対象行を制限した DELETE文を探索型DELETE と呼ぶ
```sql
-- 一部の行だけを削除する探索型DELETE
DELETE FROM <テーブル名>
 WHERE <条件>;
```

#### データ更新（UPDATE文の使い方）
- テーブルのデータを変更（更新）するには UPDATE文を使う
```sql
-- テーブルのデータを変更するUPDATE文
UPDATE <テーブル名>
   SET <列名> = <式>;
```
- 一部の行を更新するときは、WHERE句で対象行の条件を書く。WHERE句で更新対象行を制限した UPDATE文を、探索型UPDATE と呼ぶ
```sql
-- 一部の行だけを変更する探索型UPDATE
UPDATE <テーブル名>
   SET <列名> = <式>
 WHERE <条件>;
```
- UPDATE文で列を NULLクリアすることもできる。ただし、NOT NULL制約のついていない列に限る
- 複数の列を同時に更新するには、UPDATE文の SET句で更新対象の複数の列をカンマ区切りで並べる

#### トランザクション
- トランザクションは、**セットで実行されるべき1つ以上の更新処理の集まり**のこと。トランザクションを使用すれば、データベースにおけるデータ更新処理の確定や取り消しなどを管理することができる
- トランザクションの処理を終わらせるコマンドとして、**COMMIT**（処理の確定）、**ROLLBACK**（処理の取り消し）の2つがある
- DBMS のトランザクションには、原子性（Atomicity）、一貫性（Consistency）、独立性（Isolation）、永続性（Durability）という、守らなければならない約束事がある。これら4つの頭文字をとり、**ACID特性**とも呼ばれる
- COMMIT のイメージ
```
# COMMITのイメージ ＝ 処理が一直線に流れる
① トランザクション開始文
↓
② 更新文（DML）実行
↓
③ COMMIT実行
終了状態：② の更新がすべて反映されている
```
- ROLLBACK のイメージ
```
# ROLLBACKのイメージ ＝ スタート地点まで一気にUターンする
① トランザクション開始文
↓
② 更新文（DML）実行
↓
③ ROLLBACK実行

```

### SQLの基本まとめ
#### SELECTは何をする命令か？
SELECT は、データベースから必要なデータを取り出して表示する命令。
たとえば、「商品一覧を表示したい」「価格が1,000円以上の商品だけ見たい」といったときに使用する。
イメージとしては、本棚から必要な本を取り出して読むようなもの。
データを見るだけなので、内容は変更されない。

#### INSERTは何をする命令か？
INSERT は、新しいデータをデータベースに追加する命令。
たとえば、新しい商品を登録したり、新しい会員情報を追加したりするときに使用する。
イメージとしては、名簿に新しい人の名前を書き加えるようなもの。

#### UPDATEは何をする命令か？
UPDATE は、すでに登録されているデータを変更する命令。
たとえば、商品の価格を変更したり、会員の住所を更新したりするときに使用する。
イメージとしては、名簿に書かれている情報を書き直すようなもの。

#### DELETEは何をする命令か？
DELETE は、データベースに登録されているデータを削除する命令。
たとえば、販売終了した商品や退会した会員の情報を削除するときに使用する。
イメージとしては、名簿から不要になった人の情報を消すようなもの。

#### トランザクションは何をするものか？
トランザクションとは、複数の SQL文をひとまとまりの処理として扱う仕組み。
たとえば、銀行の振り込みでは、
1. Aさんの口座からお金を引き出す
2. Bさんの口座へお金を入れる
という2つの処理を行う。
もし、途中でエラーが発生した場合、「引き出しだけ成功して、入金は失敗した」という状態になってしまうと困ってしまう。
そのため、全ての処理が成功したときだけ確定し、途中で失敗したら最初の状態に戻せるようにするのがトランザクション。

#### COMMITとROLLBACKの違い
どちらもトランザクションで使用する命令。
##### COMMIT
COMMIT は、トランザクション内で行った変更を確定する命令。
変更内容がデータベースに正式に保存され、元に戻らなくなる。
例えるなら、書類に最終確認をして「提出する」イメージ。

##### ROLLBACK
ROLLBACK は、トランザクション内で行った変更を取り消し、開始前の状態に戻す命令。
途中で誤った更新をしてしまった場合でも、変更をなかったことにできる。
例えるなら、書類を書き終えたあとに「やっぱりやり直そう」と提出前の状態に戻すイメージ。

|命令   |役割   |
|---|---|
|SELECT   |データを取り出して表示する   |
|INSERT   |新しいデータを追加する   |
|UPDATE   |登録されているデータを変更する   |
|DELETE   |登録されているデータを削除する   |
|トランザクション   |複数の処理をひとまとまりとして実行し、成功・失敗を管理する   |
|COMMIT   |変更内容を確定する   |
|ROLLBACK   |変更内容を取り消し、元の状態に戻す   |
