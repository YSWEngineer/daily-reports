#### STEP2：PostgreSQL公式のリポジトリを追加する
##### ① 準備として必要なツールをインストールする
```
sudo apt install vim gnupg2 -y
```

##### ② 署名鍵をダウンロードして登録する
```
curl -fsSL https://www.postgresql.org/media/keys/ACCC4CF8.asc | sudo gpg --dearmor -o /etc/apt/trusted.gpg.d/postgresql.gpg
```

|パーツ   |意味   |
|---|---|
|curl -fsSL https://...asc   |PostgreSQL公式サイトから「鍵」のファイルをダウンロードする   |
|/|（パイプ）   |ダウンロードした内容を次のコマンドにそのまま渡す   |
|sudo gpg --dearmor -o /etc/apt/trusted.gpg.d/postgresql.gpg   |受け取った鍵をシステムが読み込める形に変換して保存する   |

##### ③ リポジトリの場所を登録
```
sudo sh -c 'echo "deb https://apt.postgresql.org/pub/repos/apt $(lsb_release -cs)-pgdg main" > /etc/apt/sources.list.d/pgdg.list'
```


### psqlって何？
#### 「psql」という名前の由来
公式ドキュメントでの説明はこうなっている。

> psql — PostgreSQL interactive terminal（PostgreSQL対話型ターミナル）

つまり、「PostgreSQL Interactive Terminal」の短縮名。

|項目   |内容   |
|---|---|
|psqlの正式名称   |PostgreSQL Interactive terminal の略   |
|psqlは慣習的な表記？   |公式にこの名前で開発・提供されているコマンド   |
|psqlとは？   |SQLコマンドを対話的に打ち込んで、PostgreSQLサーバーとやり取りするためのプログラム   |

ちなみに、PostgreSQL 自体も正式名称が長いため口語では「ポストグレス」「ポスグレ」と略して呼ばれることが多い。

#### 参考リンク
- [PostgreSQL: Documentation: 18: psql](https://www.postgresql.org/docs/current/app-psql.html)
- [PostgreSQL: Documentation: 8.4: A Brief History of PostgreSQL](https://www.postgresql.org/docs/8.4/history.html)

### psql内の基本コマンドを試してみる
`postgres=#`のプロンプトが出ている状態のまま、基本コマンドを一つひとつ確認する。
#### ① データベース一覧を見る
```sql
\l
```
どんなデータベースが最初から存在しているか確認できる。
```sql
-- データベース一覧を見る
postgres=# \l
                                                   List of databases
   Name    |  Owner   | Encoding  | Locale Provider | Collate | Ctype | ICU Locale | ICU Rules |   Access privileges   
-----------+----------+-----------+-----------------+---------+-------+------------+-----------+-----------------------
 postgres  | postgres | SQL_ASCII | libc            | C       | C     |            |           | 
 template0 | postgres | SQL_ASCII | libc            | C       | C     |            |           | =c/postgres          +
           |          |           |                 |         |       |            |           | postgres=CTc/postgres
 template1 | postgres | SQL_ASCII | libc            | C       | C     |            |           | =c/postgres          +
           |          |           |                 |         |       |            |           | postgres=CTc/postgres
(3 rows)
```

PostgreSQL をインストールした直後は、デフォルトで3つのデータベースが用意されている。

|データベース名   |役割   |
|---|---|
|postgres   |デフォルトの作業用データベース。ユーザーが特に指定しない場合、ここに接続される。   |
|template0   |変更不可のまっさらなテンプレート。新しいデータベースを作る際の大元になる   |
|template1   |カスタマイズ可能なテンプレート。CREATE DATABASE で新規データベース作成時に、通常はこちらがコピーされる。   |

##### 各列の意味（気になる範囲で軽く）
- `Owner`：そのデータベースの所有者。
- `Encoding`：文字コード。`SQL_ASCII`は文字設定の種類。
- `Access privileges`：アクセス権限の設定。

#### ② ロール（ユーザー）一覧を見る
```sql
\du
```
```sql
postgres=# \du
                             List of roles
 Role name |                         Attributes                         
-----------+------------------------------------------------------------
 postgres  | Superuser, Create role, Create DB, Replication, Bypass RLS
```

##### 表示内容の確認
現在、`postgres`というロール（ユーザー）が1つだけ存在していることがわかる。

##### Attributes（属性）列の意味
`postgres`というロール（ユーザー）には以下の権限が付与されている。

|属性   |意味   |
|---|---|
|Superuser   |全ての制限を無視できる最上位の管理者権限   |
|Create role   |新しいロール（ユーザー）を作成できる権限   |
|Create DB   |新しいデータベースを作成できる権限   |
|Replication   |レプリーケーション（データベースの複製・同期）に関する権限   |
|Bypass RLS   |Row Level Security（行単位のアクセス制限）を無視できる権限   |

おそらく、`postgres`ロール（ユーザー）は、Linux でいう`root`ユーザーのような権限を持つ管理者のようなイメージ🤔

### ユーザーの追加・削除など基本の操作を覚える
#### ユーザーの追加
`postgres`しかない状態から、テスト用の新しいロール（ユーザー）を作ってみる。
```sql
-- testuserロール（ユーザー）の追加
postgres=# CREATE ROLE testuser WITH LOGIN PASSWORD 'password123';
CREATE ROLE
```
`CREATE ROLE`が返ってきているのは、コマンドが正常に実行された証拠。

再度、`\du`を実行して、`testuser`が増えているか確認する。
```sql
postgres=# \du
                             List of roles
 Role name |                         Attributes                         
-----------+------------------------------------------------------------
 postgres  | Superuser, Create role, Create DB, Replication, Bypass RLS
 testuser  | 
```
`testuser`の`Attributes`（属性）欄が空欄なのは、`postgres`ロール（ユーザー）とは違い、`testuser`には特別な権限を持っていないから。
「**ログインはできるけど、データベースやロールを新規作成する権限はない**」という最低限の状態になっている。

#### ユーザーの削除
```sql
-- testuserロール（ユーザー）の削除
postgres=# DROP ROLE testuser;
DROP ROLE
```
再度、`\du`を実行して、`testuser`が削除されているか確認する。
```sql
postgres=# \du
                             List of roles
 Role name |                         Attributes                         
-----------+------------------------------------------------------------
 postgres  | Superuser, Create role, Create DB, Replication, Bypass RLS
```

### 気になった各コマンドについて
#### \l の意味
`l`は「list」（一覧）の頭文字。`\l` = 「データベースを一覧表示する」コマンド。

#### \du の意味
`\d`から始まるコマンド群には、それぞれ共通のルールがある。
- `\d` = **d**escribe（説明する・一覧表示する）の頭文字。
- `\d`のあとに続くアルファベット1文字が「何を」説明するかを表す。

|コマンド   |対象   |覚え方   |
|---|---|---|
|\dt   |**t**able   |**d**escribe **t**ables   |
|\di   |**i**ndex   |**d**escribe **i**ndexes   |
|\dn   |schema   |**d**escribe schema（**n**amespace）   |
|\dv   |**v**iew   |**d**escribe **v**iews   |
|\du   |role / **u**ser   |**d**escribe **u**sers   |

つまり`\du`は「**d**escribe **u**sers」（ユーザーを説明する = ユーザー一覧を表示する）という組み合わせになる。

### psqlコマンドだけでPostgreSQLに接続できるようにしたい
再び PostgreSQL に接続するときは、以下のコマンドを入力する。
```
# VPSに接続したのち、以下のコマンドでPostgreSQLに接続する
sudo -u postgres psql
```
もっと簡単な方法がないのかな？と思い検索してみると、**自分自身の OSユーザー名と同じロールを作る**と`sudo`なしで直接`psql`と打つだけで接続できるようになるとわかった。

#### STEP1：yoshiwoという名前のロールを作成する
Debian のユーザー名が`yoshiwo`なので、PostgreSQL に同じ名前のロールを作成する。
この設定は、通常の Linux のプロンプト（VPS に接続された状態）から始めること。
```
# VPSに接続して以下のコマンドを入力
sudo -u postgres createuser --interactive yoshiwo
```
これを実行すると、対話形式でいくつか質問される。
まずは、`sudo`のパスワード。
```
[sudo] password for yoshiwo:
```
「新しいロールに管理者権限（スーパユーザー）を与えますか？（Yes / No）」と訊かれるので、`n`（No）を選択。
```
Shall the new role be a superuser? (y/n) n
```
「新しいロールにデータベースの作成を許可しますか？（Yes / No）」と訊かれるので、`y`（Yes）を選択。
```
Shall the new role be allowed to create databases? (y/n) y
```
「新しいロールに、さらに新しいロールを作成することを許可しますか？（Yes / No）」と訊かれるので、`n`（No）を選択。
```
Shall the new role be allowed to create more new roles? (y/n) n
```

#### STEP2：作成できたか確認する
```
# 以下のコマンドを入力してロールが作成できたか確認する
sudo -u postgres psql -c "\du"
```
すると、DB に作成した`yoshiwo`ロールが`Create DB`の権限を持った状態で追加されているのを確認できる。
```
                             List of roles
 Role name |                         Attributes                         
-----------+------------------------------------------------------------
 postgres  | Superuser, Create role, Create DB, Replication, Bypass RLS
 yoshiwo   | Create DB
```

#### STEP3：sudoなしで接続できるか試す
```
psql
```
しかし、以下のようなエラーが表示された。
```
yoshiwo@tk2-262-40865:~$ psql
psql: error: connection to server on socket "/var/run/postgresql/.s.PGSQL.5432" failed: FATAL:  database "yoshiwo" does not exist
```
その場合は、既存のデータベース名（デフォルトの`postgres`）を明示して接続すれば大丈夫。
```
yoshiwo@tk2-262-40865:~$ psql -d postgres
psql (16.14 (Debian 16.14-1.pgdg12+1))
Type "help" for help.

postgres=>
```
`\q`で psql を終了し、シェルのプロンプトに戻ったら、ユーザー名と同じ名前のデータベースを作成する。
```
yoshiwo@tk2-262-40865:~$ createdb yoshiwo
```
`psql`コマンドを入力すると......
```
yoshiwo@tk2-262-40865:~$ psql
psql (16.14 (Debian 16.14-1.pgdg12+1))
Type "help" for help.

yoshiwo=>
```
無事に接続できている。
プロンプトが`yoshiwo=>`になっているのは、「`yoshiwo`ロールとして、`yoshiwo`データベースに接続している」から。

#### プロンプトの # と > の違いについて

|プロンプト  |意味   |
|---|---|
|#（シャープ）   |接続しているロールが管理者権限を持っている   |
|>（不等号）   |接続しているロールが管理者権限を持っていない（一般ユーザー）   |
