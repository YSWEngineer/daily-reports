### 自分の解答との違い
#### 違い1：locationブロックの書き方
##### 模範解答
```
location / {
    root /var/www/msastudy.work/;
    index index.html;
}
```
##### 自分の解答
```
root /var/www/site1;
index index.html;

location / {
    try_files $uri $uri/ =404;
}
```
`root`と`index`をどこに書くかが違う。
模範解答は`location`ブロックの中に書いている。
私の解答は`location`ブロックの外に書いている。
私の書き方でも動いたが、模範解答では、`location`ブロックの中で設定対象を明示している。

#### ちょっとだけ深掘り......「明示」の意味
`root`と`index`を`location`ブロックの中に書くか外に書くかの違い。
```
# 模範解答：locationブロックの中に書く
location / {
    root /var/www/msastudy.work/;  ← locationの中
    index index.html;              ← locationの中
}

# 私の解答：locationブロックの外に書く
root /var/www/site1;   ← locationの外
index index.html;      ← locationの外

location / {
    try_files $uri $uri/ =404;
}
```
「この`root`と`index`は`/`へのアクセスに対して適用される設定ですよ！」というのが、`location`ブロックの中に書いてあることで読み手に伝わりやすい、という意味で「明示的」。

##### 復習：/ について
`/`は URL のパス（場所）を表している。
例えば Webサイトにアクセスするとき、URL はこういう構造になっている。
###### URLの構造
```
https://site1.ysw-engineer.com/about/profile.html
        ↑                     ↑
     ドメイン名              パス（場所）
```
ドメイン名は「どのサーバーか」を表し、パスは「そのサーバーの中のどこか」を表す。

###### パスの例
```
https://site1.ysw-engineer.com/
                              ↑
                     パスは「/」だけ → トップページ

https://site1.ysw-engineer.com/about/
                              ↑
                     パスは「/about/」 → aboutページ

https://site1.ysw-engineer.com/about/profile.html
                              ↑
                     パスは「/about/profile.html」
```

###### location / の意味
```
location / {
    root /var/www/site1;
    index index.html;
}
```
これは「`/`から始まるパスへのアクセスが来たら、`/var/www/site1`の中のファイルを返してね」という意味。
`/`はすべてのパスの先頭にあるため、より具体的な location指定がない場合は、サイト全体に対する設定として使われる。

###### 具体的なイメージ
```
ブラウザで https://site1.ysw-engineer.com/ にアクセス
   ↓
nginx が「パスは / だな」と判断
   ↓
location / の設定を見る
   ↓
/var/www/site1/index.html を返す
```
一言でまとめると「`location /`はサイト全体へのアクセスに対して、どのファイルを返すかを定義している」。

#### 違い2：SSL関連の追加設定
模範解答には私の解答にない行が2つあった。
```
include /etc/letsencrypt/options-ssl-nginx.conf;
ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;
```
それぞれの意味は以下のとおり......
・`include /etc/letsencrypt/options-ssl-nginx.conf;`
→ certbot が用意した SSL の推奨設定を読み込む（使用する SSL のバージョンや暗号化方式などのセキュリティ設定）。

・`ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;`
→ DH（ディフィー・ヘルマン）鍵交換という暗号化の仕組みに使うパラメータファイルを指定する（通信をより安全にするための追加設定）。

↑この2行は certbot が自動で追記することが多い設定で、セキュリティを強化するもの。

#### まとめ
模範解答と私の解答の比較
##### 模範解答
・ `include`で共通化はしていない
・ SSL追加設定（`options-ssl-nginx.conf`, `ssl-dhparams`）あり

##### 私の解答
・ `include`で共通化する（メンターさんの指摘を反映して）
・ ログをディレクトリで管理する（メンターさんの指摘を反映して）
・ `try_files`で404設定あり
