### 9.1 映画データは全て利用者入力
#### 復習：hヘルパーとは？
`h`は、HTML で特別な意味を持つ文字を、文字として表示できる形に変換するためのメソッド。
たとえば、次のような変換を行う。
|変換前   |変換後   |
|---|---|
|<   | &lt;  |
|>   |&gt;   |
|"   |&quot;   |

これを**HTMLエスケープ**という。

#### hヘルパーを確認する
```ruby
helpers do
  def h(value)
    Rack::Utils.escape_html(value)
  end
end
```
それぞれの役割は次のとおり。
|コード   |役割   |
|---|---|
|helpers do   |Sinatra で利用できるヘルパーメソッドを定義する   |
|def h(value)   |h というメソッドを定義する   |
|value   |エスケープしたい値を受け取る   |
|Rack::Utils.escape_html(value)   |HTML で特別な意味を持つ文字を変換する   |

`h`という名前を付けたメソッドの中で、Rack が提供する`escape_html`を呼び出している。

#### データが表示されるまでの流れ
映画図鑑では、次のような流れになる。
**① 利用者**
映画のタイトルなどを入力
　　　↓
**② Sinatra**
入力値を受け取り、JSON に保存
　　　↓
**③ ERBテンプレート**
保存された値を HTML に埋め込む
　　　↓
**④ hヘルパー**
HTMLエスケープで安全に表示できる形へ変換
　　　↓
**⑤ ブラウザ**
**タグではなく文字として表示**

`h`は、入力されたデータそのものを削除したり、JSON から危険な文字列を取り除いたりするものではない。
**HTML として表示するときに、文字として安全に扱える形へ変換するもの**。

#### ジャンルも hヘルパーを使って HTMLエスケープする
映画図鑑のタイトル・監督・公開年・ジャンル・紹介文は、全て利用者が入力できる値。
画面上で選択肢になっている**ジャンル**も、ブラウザの開発者ツールなどから値を変更して送信できるため、信用してはいけない。

そのため、利用者が入力した値を HTML に表示するときは、**hヘルパーを使って HTMLエスケープする。**

### 9.2 XSS とは
XSS（クロスサイトスクリプティング）は、Cross-site scripting の略。
攻撃者が用意した JavaScript などのスクリプトが、Webサイトの一部として利用者のブラウザで実行されてしまう脆弱性のこと。

#### XSS は何が危険なのか？
たとえば、攻撃者が映画のタイトル欄に不正なスクリプトを入力したとする。
その値をエスケープせずに HTML に出力すると、ブラウザは文字列ではなくスクリプトとして解釈する可能性がある。
すると、サイトを閲覧した人のブラウザ上で、意図しない JavaScript が実行されてしまう。

実際の被害は、スクリプトの内容によって異なる。
たとえば、画面を書き換えたり、利用者の権限で不正な操作を行なったりする可能性がある。

#### hヘルパーでどう防ぐのか？
|エスケープしない場合   |エスケープする場合   |
|---|---|
|HTMLタグとして解釈される可能性がある   |文字列として表示される   |
|スクリプトが実行される可能性がある   |スクリプトとして実行されない   |

つまり、ブラウザに「これは HTML のタグではなく、単なる文字ですよ」と伝えるために HTMLエスケープを行う。

#### この節で押さえておきたいこと
<div style="
  border: 1px solid #ccc;
  padding: 16px 24px;
  width: fit-content;
  max-width: 100%;
  margin: 16px auto;
  box-sizing: border-box;
  text-align: center;
  line-height: 1.8;
">
  <strong>XSS が発生する基本的な流れ</strong><br>
攻撃者が不正なスクリプトを入力<br>
↓<br>
Webアプリがエスケープせず HTML に出力<br>
↓<br>
ブラウザがスクリプトとして解釈<br>
↓<br>
<span style="color: red;">意図しないスクリプトが実行される</span>
</div>

### 9.3 安全な状態で入力してみる
使用する文字列は次の内容。
```html
<script>alert("xss")</script>
```
これは JavaScript のアラートを表示する簡単なテスト用のスクリプト。
通常ならブラウザで実行される可能性があるが、HTMLエスケープによって実行されないことを確認する。

また、HTMLレスポンスでは、次のように変換されていることを確認する。
```html
&lt;script&gt;alert(&quot;xss&quot;)&lt;/script&gt;
```

#### 文字参照（Character Reference）/ HTMLエンティティ
`&lt;`や`&gt;`などは、**HTML で特別な意味を持つ記号を表現するための書き方**。
文字参照（Character Reference）や HTMLエンティティとも呼ばれる。

|HTML での書き方   |表示される文字   |意味   |
|---|---|---|
|\&lt;   |<   |less than（小なり）   |
|\&gt;   |>   |greater than（大なり）   |
|\&quot;   |"   |quotation mark（二重引用符）   |
|\&amp;   |&   |ampersand (アンパサンド)   |
|\&#39;   |'   |apostrophe（シングルクォート）   |

```erb

```

ブラウザで映画図鑑を開き、新しい映画を登録する画面を開く。
映画のタイトル欄に以下の文字列を入力する。
```html
<script>alert("xss")</script>
```
監督・公開年・ジャンル・紹介文などは適当なテスト用の値を入力する。

### 9.5 属性値で壊れる入力
#### HTML の属性値とは？
HTMLタグの中に設定される情報のことを**属性値**という。
たとえば、次のコード。
```html
<input type="text" value="映画のタイトル">
```
- `input`：入力欄を作るタグ
- `type`：入力欄の種類
- `value`：入力欄に表示する初期値

`value="..."`のように、属性値は通常、ダブルクォーテーション`"`で囲まれている。

### 9.6 textarea で壊れる入力
`textarea`は、入力欄の開始タグと終了タグの間に初期値を記述する。
```html
<textarea>ここが初期値になる</textarea>
```
もし利用者が次の文字列を入力した場合、
```html
</textarea><script>alert("xss")</script>
```
エスケープせずに出力すると、最初の`</textarea>`によって本来の入力欄が途中で終了してしまう。
つまり、`textarea`でも`h`によるエスケープが必要。

### 9.7 \<script>だけ防げばよいわけではない
`h`ヘルパーは万能ではない。
JavaScript の中や URL など、別の場所に値を埋め込む場合には、それぞれに適した対策が必要となる。

### 9.8 映画図鑑で h を使う場所
この節で重要なポイントは、**利用者入力を画面に表示している場所を見つけ、`h`ヘルパーを使うこと。**

### 9.9 改行表示は CSS で扱う
映画の紹介文は、複数行になることがあるかもしれない。
たとえば、次のような文章、
```text
主人公は不思議な世界へ迷い込みます。
そこで出会った仲間とともに冒険を始めます。
```
ところが、HTML では通常、文章中の改行がそのまま画面に反映されるとは限らない。
そこで**CSS**を使う。

#### white-space とは？
```css
.movie-description {
  white-space: pre-line;
}
```
CSSファイルの中のコードにある`white-space`は、HTML内の空白や改行をブラウザでどのように表示するかを指定する CSSプロパティである。
そこに`pre-line`を指定すると、文章中の改行を画面にも反映できる。
|指定値   |主な動作   |
|---|---|
|normal   |通常の表示。連続する空白や改行は基本的にまとめられる   |
|pre   |空白や改行を保持し、通常は折り返さない   |
|pre-line   |改行を保持し、連続する空白はまとめる   |

### 考えてみよう
- なぜ\<script>という文字列だけを禁止しても十分ではないのでしょうか。
**回答**：\<script>以外にも、HTML の属性値や`textarea`を途中で終了させるなど、さまざまな方法で不正な HTML を挿入できるため。

- なぜ ERB の`<%= %>`だけで安全だと考えてはいけないのでしょうか。
**回答**：`<%= %>`は Ruby の値を HTML に出力するための記法であり、自動的に HTMLエスケープしてくれるわけではないから。

- なぜ紹介文の改行表示を Ruby の`gsub`ではなく CSS で扱うのでしょうか。
**回答**：Ruby で HTMLタグを組み立てると、利用者入力のエスケープが複雑になるため。文字の安全性は`h`ヘルパーを用いて、改行などの見た目は CSS の`white-space: pre-line;`で調整する。
