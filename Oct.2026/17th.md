## 💡 本日の学び・気付き
### FBC Press：Sinatra
#### 学習の目的
- Sinatra を通して、Webアプリケーション開発の基礎を身に付ける。
- 「リクエストとレスポンスの往復」を理解する。

#### Sinatraで学ぶ理由・特徴
- Sinatra は小さな Webフレームワークである。
- URL、HTTPメソッド、Rubyの処理の結び付きが、コードにそのまま表れる。
- Sinatra のアプリは小さく保つことができ、ハンズオンでは`app.rb`を中心に処理を追える。
- 一つのリクエストが届いてからレスポンスが返るまでの流れを、自分で追いやすい。
- Sinatra も Rails も、Rack という共通の土台を利用している。

### 第1章：Webアプリケーションはどこで動いているのか
#### 1.1 ブラウザだけでは映画図鑑は動かない
- ブラウザは HTML や CSS を読み取り、画面を表示する。
- ブラウザは Ruby のプログラムを直接実行しない。サーバーへ処理を依頼し、その結果を受け取る。

#### 1.2 URLはファイル名ではなくリクエストの宛先
HTMLファイルを開くときのファイルの場所と、Webアプリケーションへアクセスするときの URL は異なる。

例：`http://localhost:4567/movies`

| 部分 | 例 | 役割 |
|---|---|---|
| スキーム | `http` | 通信の仕組みを表す |
| ホスト | `localhost` | 接続先を表す |
| ポート番号 | `4567` | 接続先のプログラムが待ち受ける入口を表す |
| パス | `/movies` | リクエストの対象を表す |

- **ルーティング**：HTTPメソッドや URL のパスと、実行する処理を対応付ける仕組み。
- **サーバー**：コンピューターそのものを指す場合と、リクエストを受け付けるプログラムを指す場合がある。今回の教材では、主に後者を指す。

#### 1.3 リクエストとレスポンスの往復
- **リクエスト**：ブラウザなどからサーバーへ送る要求。
- **レスポンス**：サーバーが要求を処理して返す応答。

映画一覧を開くときの流れは次のとおり。

1. ブラウザが`/movies`へリクエストを送る。
2. Webアプリケーションがリクエストを受け取る。
3. Webアプリケーションが映画の一覧を含むレスポンスを作る。
4. ブラウザがレスポンスを受け取り、HTMLを画面に表示する。

このとき、Rubyのコードは主に 2 と 3 の処理で動く。

#### 1.4 HTTPのメッセージをテキストとして読む
ブラウザと Webアプリケーションは、HTTP という通信上の取り決めに従って情報をやり取りする。

| 確認するもの | 例 | 分かること |
|---|---|---|
| HTTPメソッド | `GET` | リクエストの目的 |
| パス | `/movies` | リクエストの対象 |
| ステータスコード | `200 OK` | 処理結果 |
| ヘッダー | `Content-Type: text/html` | メッセージに関する追加情報 |
| レスポンス本文 | HTMLの内容 | ブラウザに返されたデータ |

- `404 Not Found`は、リクエストされたリソースが見つからないことを表すステータスコード。

#### 1.5 HTMLを誰が用意するか
HTMLをブラウザに表示する方法には、次のようなものがある。

1. 自分の PC にある HTMLファイルを直接開く。
2. Webサーバーに保存されている HTMLファイルを受け取る。
3. Ruby などのプログラムが生成した HTML を Webサーバーから受け取る。

| 開き方 | HTTP のやり取り | HTML の用意の仕方 |
|---|---|---|
| 手元の HTMLファイルを直接開く | なし | ブラウザが手元のファイルを読む |
| Webサーバー上の静的な HTML を開く | あり | サーバーが用意済みの HTML を返す |
| 映画図鑑の画面を開く | あり | Ruby の処理などによって HTML を生成する |

#### 1.6 映画図鑑で作るリクエストの入り口
映画図鑑では、一覧・詳細・登録・編集・削除の機能を用意する。
すべてを一つの画面や処理に詰め込むのではなく、目的に応じた URL とHTTPメソッドに分ける。

| 操作 | ブラウザで起こすこと | Webアプリケーションの処理 |
|---|---|---|
| 一覧を見る | 一覧の URL を開く | 保存されている映画を読み込んで表示する |
| 詳細を見る | 映画の詳細ページへ移動する | ID で映画を探して表示する |
| 登録する | フォームを送信する | 新しい ID を付けて映画を保存する |
| 編集する | 編集フォームを送信する | ID が一致する映画を更新する |
| 削除する | 削除用のフォームを送信する | ID が一致する映画を削除する |

#### 1.7 Networkパネルで往復を確かめる
Chrome DevTools の Networkパネルを使い、ブラウザと Webアプリケーションの間で行われる通信を確認する。

**確認手順**

1. Chrome で DevTools を開く（macOSでは`Command + Option + I`）。
2. `Network`パネルを選択する。
3. DevTools を開いたままページを再読み込みする（`Command + R`）。
4. リクエスト一覧から、ページに対応する`document`または`Doc`の行を選ぶ。
5. `Headers`タブと`Response`タブを確認する。

### 第2章：Sinatraを始める
#### 2.1 Sinatraが結ぶリクエストとRuby
```ruby
get "/movies" do
  "映画図鑑"
end
```

このように、HTTPリクエストとRubyの処理を対応付けたものを**ルート**と呼ぶ。

| コード | 対応するもの |
|---|---|
| `get` | HTTPメソッドの GET |
| `"/movies"` | リクエストのパス`/movies` |
| `do` から `end` | リクエストが一致したときに実行する処理 |
| `"映画図鑑"` | レスポンス本文になる文字列 |

- `get`は Sinatra が用意するメソッド。
- `get "/movies"`と書くことで、HTTP の`GET /movies`とRubyの処理を結び付けられる。
- Sinatra のように、特定の目的に合わせて用意された書き方を**DSL**（ドメイン固有言語）と呼ぶ。

まずは、HTTPメソッド・パス・Ruby の処理が対応していることを押さえる。

#### 2.2 作業用ディレクトリを用意する
ターミナルで作業用ディレクトリを作成し、Gitリポジトリを初期化した。
```zsh
mkdir sinatra-movies
cd sinatra-movies
git init
pwd
```
`pwd`で`/Users/yoshiwo/sinatra-movies`と表示されることを確認した。

#### 2.3 バージョンを揃える3つのファイル
Ruby や Gem は、バージョンによって書き方や動作が変わることがある。
そのため、プロジェクトで使用するバージョンを管理する。

| ファイル | 役割 | 本書での例 |
|---|---|---|
| `.ruby-version` | 使用するRubyのバージョンを指定する | Ruby 4.0.6 |
| `Gemfile` | 必要なGemと許容するバージョン範囲を指定する | Sinatra 4.2系 |
| `Gemfile.lock` | 実際に選ばれたGemとバージョンを記録する | Sinatra 4.2.1など |

`.ruby-version`と`Gemfile`は自分で作成し、`Gemfile.lock`は`bundle install`を実行すると生成される。

##### STEP 1：`.ruby-version`を作成する
作業場所が`sinatra-movies`であることを確認し、次のコマンドでファイルを作成した。
```zsh
printf '4.0.6\n' > .ruby-version
```

ファイルの中身を確認する。

```zsh
cat .ruby-version
```

`4.0.6`と表示された。

続いて、Rubyのバージョンを確認したところ、最初は次のエラーが発生した。

```text
rbenv: version `4.0.6' is not installed
```

`.ruby-version`に指定したRuby 4.0.6が、まだインストールされていないことが原因だった。

##### STEP 2：Ruby 4.0.6をインストールする

Rubyのインストールに必要な`ruby-build`が古く、最初はRuby 4.0.6のインストール定義を確認できなかった。

`ruby-build`を更新した後にインストールを試みたが、今度はOpenSSLを見つけられず、ビルドに失敗した。

原因を調べたところ、Mac の CPUアーキテクチャは`arm64`だった一方で、利用していた Homebrew は Intel版の`/usr/local`にインストールされていた。

そこで、既存の Intel版Homebrewは削除せず、Apple Silicon 向けのHomebrewを`/opt/homebrew`に追加した。zshの設定を変更してARM版を優先し、ARM版の`rbenv`、`ruby-build`、`openssl@3`を用意した。

その後、Ruby 4.0.6のインストールに成功した。

```text
ruby 4.0.6 (2026-07-14 revision 03b6d3f889) +PRISM [arm64-darwin24]
```

`rbenv version`でも、プロジェクトの`.ruby-version`で指定したRuby 4.0.6が選択されていることを確認した。

さらに、Ruby から OpenSSL を読み込めることも確認できた。

```zsh
ruby -ropenssl -e 'puts OpenSSL::OPENSSL_VERSION'
```

実行結果：

```text
OpenSSL 3.5.9 29 Sep 2026
```

今回の対応で、Ruby 4.0.6をインストールし、OpenSSL も利用できる状態になった。

主な結果は次のとおり。

```zsh
echo >> ~/.zprofile
echo 'eval "$(/opt/homebrew/bin/brew shellenv zsh)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv zsh)"
```

次のコマンドで、ARM版Homebrew が優先されていることを確認した。

```zsh
brew --prefix
type -a brew
```

`brew --prefix`の結果は`/opt/homebrew`となった。


- `ruby-build 20261013`

最後に、Ruby 4.0.6をインストールし、バージョンと OpenSSL の動作を確認した。

##### STEP 3：`Gemfile`を用意する

Vimで`Gemfile`を作成し、以下の内容を入力して保存した。

```ruby
source "https://rubygems.org"

ruby "4.0.6"

gem "puma", "~> 8.0.0"
gem "rackup", "~> 2.3.0"
gem "sinatra", "~> 4.2.0"
```

それぞれの役割は次のとおり。

- `source "https://rubygems.org"`：Gem を取得する配布元を指定する。
- `ruby "4.0.6"`：このプロジェクトで使用する Rubyのバージョンを指定する。

| Gem | 役割 |
|---|---|
| Puma | Webサーバーとして HTTPリクエストを受け付ける |
| rackup | Rackベースの Webアプリケーションの起動を補助する |
| Sinatra | URL に応じた処理を実行し、レスポンスを返す Webフレームワーク |

`"~> 4.2.0"`などの指定は、使用を許可するバージョンの範囲を表している。

今回は、`Gemfile`の作成と保存まで完了した。
