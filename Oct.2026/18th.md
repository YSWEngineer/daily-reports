#### 2.4 Bundler 必要な Gem を用意する
- **Bundler** は、Gem を管理するためのツール。
- Bundler 自体も Gem の一つで、Ruby と一緒に使う。
- Gem は、別の Gem を必要とすることがある。
- Bundler は、`Gemfile`を読み、同時に使える Gem の組み合わせを選ぶ。そして、選んだ結果を`Gemfile.lock`に記録する。
- 同じ`Gemfile.lock`を使えば、複数の人が同じ Gem の組み合わせでアプリを動かせる。

##### STEP1：Bundler のバージョンを確認する
```zsh
bundle -v
```

Bundler のバージョンが 4.0.16 と表示された場合、次のコマンドで指定したバージョンを使えることを確認する。
```zsh
bundle _4.0.16_ -v
```

##### STEP2：Bundler で必要な Gem をインストールする
```zsh
bundle _4.0.16_ install
```

`Bundle complete!`が表示された場合、`Gemfile.lock`が生成されたことも確認する。

#### 2.7 Puma、Rack、Sinatra の受け渡し
ここでのポイントは、Puma・Rack・Sinatra がそれぞれ異なる役割を持っていること。

##### Puma：Webサーバー
ブラウザから届いた HTTPリクエストを受け付け、Webアプリケーションへ渡す。
また、アプリケーションから返ってきたレスポンスをブラウザへ送り返す。

##### Rack：共通のインターフェース
Puma と Sinatra が、リクエストやレスポンスを受け渡すための共通の約束事。
Rack自体が、Puma や Sinatra のように独立したサーバーとして動くわけでない。

##### Sinatra：Webフレームワーク
リクエストに合うルートを選び、Ruby の処理を実行してレスポンスを作る。
先程ファイルの内容に書いた`get "/" do ... end`も、ここで利用される。

##### ブラウザで http://localhost:4567/ を開いたときの動き
1. ブラウザが`GET /`を送る。
2. Puma が HTTPリクエストを受け付ける。
3. Rack の共通インターフェースを通じて、Sinatra にリクエストが渡される。
4. Sinatra が`get "/"`の処理を実行し、文字列をレスポンスとして返す。
5. Puma がレスポンスをブラウザへ送り、画面に表示される。

##### Rack と rackup
- **Rack**：受け渡しの共通インターフェース。
- **rackup**：サーバーの起動を補助する Gem。rackup が別の Webサーバーとして Puma と並んで動いているわけではない。

##### 変更前と変更後を比べてみる
|項目   |変更前   |変更後   |
|---|---|---|
|GET / の処理   |文字列を返す   |/movies へのリダイレクトを返す   |
|最終的な表示   |映画図鑑を作ります   |映画図鑑   |
|アドレスバー   |/   |/movies   |

ここで押さえたいのは、`redirect "/movies"`が`"/movies"`の処理を直接呼び出しているわけではない、ということ。
実際には、次のような流れになる。
1. **ブラウザ**：`GET /`を送る。
2. **Sinatra**：`redirect "/movies"`を実行する。
3. **ブラウザがリダイレクトを受け取る**：次に`/movies`へアクセスする。
4. **Sinatra**：`GET /movies`のルートを実行する。
5. **ブラウザ**：「映画図鑑」を表示する。

##### redirect とヘルパーメソッド
- `redirect`：ブラウザに別の URL へ移動するよう伝える、Sinatra が用意したメソッド。
- **ヘルバーメソッド**：よく使う処理を簡単に実行できるように用意された補助的なメソッド。
- **メソッド**：特定の処理を実行する仕組み。
- **redirectの流れ**：最初のリクエストに対してリダイレクトのレスポンスを返し、ブラウザが移動先へ新しいリクエストを送る。

|---|---|---|
|GET /   |redirect "/movies"   |リダイレクトのレスポンスを返す   |
|GET /movies   |"映画図鑑"   |文字列をレスポンス本文として返す   |

ここで大切なのは、`redirect "/movies"`が`get "/movies"`の処理を直接呼び出しているわけではないこと。
最初のリクエストに対してリダイレクトのレスポンスが返り、それを受け取ったブラウザが、改めて`/movies`へ GETリクエストを送る。

##### 理解度チェック
- Puma：ブラウザから届いた HTTPリクエストを受け付け、Rack のインターフェースを通じて Webアプリケーションへ渡す。また、アプリケーションから返されたレスポンスをブラウザへ送り返す。
- Rack：Puma と Sinatra がリクエストやレスポンスを受け渡すための共通の約束事（インターフェース）。
- Sinatra：HTTPメソッドとパスに一致するルートを選び、Ruby の処理を実行してレスポンスを返す。
- `get "/"`：ルートURL`/`への GETリクエストに対応する処理を定義する。今回のコードでは、`"映画図鑑"`という文字列をレスポンス本文として返す。
- `redirect "/movies"`：`/movies`へのリダイレクトレスポンスを返す。ブラウザはそのレスポンスを受け取ると、新たに`/movies`へ GETリクエストを送る。

##### get と redirect の違い
|書き方   |役割   |
|---|---|
|get "/movies" do ... end   |GETリクエストに対応する処理を定義する   |
|redirect "/movies"   |ブラウザに移動先を伝え、次のリクエストを促す   |
