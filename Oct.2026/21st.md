### 3.2 vies/ と ERBテンプレート
`sinatra-movies`ディレクトリに`views`ディレクトリを作り、その中に`index.erb`ファイルを作成し、HTML を書く。
```
mkdir -p views
vim views/index.erb
```
```ruby
# views/index.erbファイルの中身
<h1>映画図鑑</h1>
```

次に、`app.rb`ファイルの`get "/movies"`を変更する。
```ruby
get "/movies" do
  erb :index
end
```
仕組みとしては、`erb :index`は、`views/index.erb`を読み込み、その結果をレスポンス本文として返す。
`:index`は Ruby のシンボル。
Sinatra の`erb`メソッドでは、**テンプレート名をシンボルで指定**する。

アプリを再起動して`/movies`を開くと、h1 の見出しで「映画図鑑」が表示された。
見た目は同じだが、HTML を Ruby の文字列から`views/index.erb`へ移した。

ERB では、次の二つの書き方をよく使う。
|ERB の書き方   |役割   |
|---|---|
|<% Ruby の処理 %>   |Ruby の処理を実行する。結果は画面に出力しない。   |
|<%= Ruby の式 %>   |Ruby の式を評価し、結果を HTML に出力する。   |

#### ① ERBは何の略？
ERB：Embedded Ruby の略。簡単にいうと、HTML などの文章の中に Ruby のコードを埋め込める仕組み。
例えば、HTML に映画のタイトルを表示したいとする。
通常の HTML なら、タイトルを直接書く。
```HTML
<h1>映画図鑑</h1>
```
ERB なら、Ruby の変数に入っている値を HTML に埋め込むこともできる。
```erb
<h1><%= @title %></h1>
```
ここで`@title`に「映画図鑑」が入っていれば、生成される HTML は次のようになる。
```HTML
<h1>映画図鑑</h1>
```

#### ② <% %> と <%= %> の違い
|記法   |役割   |
|---|---|
|<% Ruby の処理 %>   |Ruby の処理を実行するが、その結果は HTML に出力しない。   |
|<%= Ruby の式 %>   |Ruby の式を評価し、その結果を HTML に出力する。   |

たとえば、`<% "映画図鑑" %>`と書いても、出力されない。
一方、`<%= "映画図鑑" %>`と書くと、「映画図鑑」が出力される。

`<% %>`は繰り返しや条件分岐などの処理を制御するために使い、
`<%= %>`は変数の値などを画面に表示するために使う。
今は、`=`があれば、Ruby の式の評価結果を HTML に出力するという点を押さえればよい。

#### 3.3 layout.erb に共通の HTML構造を書く
実際の HTML文書には、`html`, `head`, `body`などの外枠も必要。
それらを複数の画面で作ろうとすると重複が増えてしまう。
そのため、役割は次のように分けられる。

`views/layout.erb`ファイル
→ HTML文書の共通の外枠を担当する。ヘッダーや本文の領域などを定義する。

`views/index.erb`ファイル
→ 映画一覧画面に固有の内容を担当する。今回なら映画図鑑の見出しなどを書く。

`views/layout.erb`ファイルの中身
```html
<!doctype html>
<html lang="ja">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>映画図鑑</title>
  </head>
  <body>
    <header>
      <a href="/movies">映画図鑑</a>
    </header>

    <main>
      <%= yield %>
    </main>
  </body>
</html>
```
Sinatra では、`views/layout.erb`を用意すると、既定で各テンプレートの外側に使われる。
ファイル内の`<%= yield %>`の位置に、`views/index.erb`ファイルの内容が入る。
`layout.erb`は HTML文書全体の共通構造を持ち、`index.erb`は映画一覧画面に固有の中身だけを持つ。

#### 表示される仕組みを言語化する
`index.erb`には`<h1>映画図鑑</h1>`しか書いていないのに、ブラウザには HTML文書として表示されるのはどうして？

`views/index.erb`
`<h1>映画図鑑</h1>`
　　　↓
`layout.erb`の`<%= yield %>`に差し込まれる
　　　↓
**完成した HTML**
HTML文書の外枠 + 映画図鑑の見出し
　　　↓
**ブラウザ**
「映画図鑑」を見出しとして表示する

つまり、`<%= %>`が出力するのは、今回の場合は`yield`によって得られるテンプレートの内容。
その HTML をブラウザが解釈することで見出しとして表示される。
```html
# layout.erb と index.erb が組み合わさった HTML
<!doctype html>
<html lang="ja">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>映画図鑑</title>
  </head>
  <body>
    <header>
      <a href="/movies">映画図鑑</a>
    </header>

    <main>
      <h1>映画図鑑</h1>	

    </main>
  </body>
</html>
```

### 3.5 Ruby の配列とハッシュから表示する

　　　↓
`views/index.erb`

#### 2つの役割

### 本日のまとめ
#### 1. app.rb で用意した映画データが、どのようにして index.erb に渡されるのか🤔
ポイントは、**インスタンス変数**`@movies`と`erb :index`の2つ。

##### STEP1：app.rb で映画データを用意する**
`app.rb`では、配列とハッシュを使って映画データを用意している。
```text
movies（配列）
複数の映画データをまとめる

1件目の映画（ハッシュ）
タイトル：月面喫茶、公開年：2042年、ジャンル：SF など

2件目の映画（ハッシュ）
タイトル：北風のリズム、公開年：2038年、ジャンル：ドラマ など
```
この時点では、映画データを Ruby の変数`movies`にまとめているだけ。

##### STEP2：@movies にデータを代入する
次に、`GET /movies`のルートでは、映画データをテンプレートから利用できるようにしている。
```ruby
@movies = movies
erb :index
```
それぞれの役割は次のとおり。
- `@movies = movies`：用意しておいた映画データを、インスタンス変数`@movies`に代入する。
- `erb :index`：`views/index.erb`をテンプレートとして使い、その内容を HTML に組み立てる。

ここで大切なのは、`@movies`と`movies`は**別の変数**であり、代入によって映画データを`@movies`から**参照できるようにしている**ということ。

##### STEP3：index.erb で映画データを表示する
`index.erb`では、インスタンス変数`@movies`を使って、映画を繰り返し表示する。
FBC Press :Sinatra では、次のような仕組みになっている。
- `<% @movies.each do |movie| %>`：映画の件数分、繰り返す。
- `<%= movie["title"] %>`：その映画のタイトルを HTML に出力する。
- `<% end %>`：繰り返しを終了する。

つまり、映画のデータを1件ずつ取り出して、HTML の表の行を作っていく。

**ここまでの流れ**
`movies`（映画データ） → `@movies`（テンプレートから使えるようにする） → `index.erb`（HTML に表示する）

#### 2. layout.erb と index.erb は、どのように組み合わさるのか🤔
ポイントは、**共通の外枠と画面ごとの内容を分けていること**。

##### それぞれの役割
- `layout.erb`：共通の外枠
HTML文書の基本構造、ページのヘッダー、本文領域などを担当する。
- `index.erb`：個別画面の内容
映画一覧の見出し、説明文、映画の表などを担当する。

`layout.erb`には、次のような記述がある。
```erb
<main>
  <%= yield %>
</main>
```
この`yield`は、個別テンプレートの内容を差し込む位置を示す。
たとえば、`index.erb`に次の HTML があれば、
```html
<h1>映画一覧</h1>
```
生成される HTML では、次のようになる。
```html
<main>
  <h1>映画一覧</h1>
</main>
```
実際には、ヘッダーや表などを含む`index.erb`の内容が差し込まれる。

##### なぜ分けるのか？
画面が増えたとき、共通の HTML を毎回書き直さなくてよくなるから。
ヘッダーなどを変更するときも、共通の`layout.erb`を修正すれば済む。
Ruby on Rails でも、このようなレイアウトと個別ビューの役割分担が使われている。

#### 3. HTML と CSS は、ブラウザにどのように取得されるのか🤔
ポイントは、**HTML と CSS は別々の HTTPリクエストで取得される**ということ。

##### STEP1：ブラウザが HTML を要求する
ブラウザで次の URL を開く。
`http://localhost:4567/movies`
　　　↓
ブラウザは、サーバーに`GET /movies`というリクエストを送る。
　　　↓
Sinatra は対応するルートを実行し、映画データを使い ERBテンプレートを処理する。
　　　↓
その結果、`layout.erb`と`index.erb`が組み合わさった HTML が、レスポンスとして返される。

##### STEP2：ブラウザが CSS を要求する
返された HTML には、次の記述がある。
```html
<link rel="stylesheet" href="/stylesheets/application.css">
```
ブラウザはこれを読み取り、CSSファイルを取得するために別のリクエストを送る。
`GET /stylesheets/application.css`
Sinatra は`public/stylesheets/application.css`に置かれた CSSファイルを返す。

##### STEP3：ブラウザが HTML と CSS を使って表示する
流れをまとめると次のようになる。
**① ブラウザ**
`GET /movies`を送信
　　　↓
**② Sinatra**
Ruby のデータと ERBテンプレートから HTML を生成
　　　↓
**③ ブラウザが HTML を受信**
HTML内の`link`要素を見つける
　　　↓
**④ CSS を別途取得**
`GET /stylesheets/application.css`
　　　↓
**⑤ ブラウザがページを表示**
HTML の構造と CSS のスタイルを組み合わせる

Networkパネルでは、次の 2つが別々の通信として表示される。
|リクエスト   |内容   |
|---|---|
|GET /movies   |Sinatra が生成する HTML   |
|GET /stylesheets/application.css   |public/ にある CSSファイル   |

今回の 3つは、実は一つの流れに繋がっている。
`app.rb`
映画データとルートを用意する
　　　↓
`index.erb` + `layout.erb`
データを HTML に埋め込み、共通の外枠と組み合わせる
　　　↓
**ブラウザが HTML を受信**
`link`要素を読み取り、CSS を別途取得する
　　　↓
**HTML + CSS**
映画一覧の Webページとして表示される
