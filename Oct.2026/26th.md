## 💡 本日の学び・気付き
### 4.5 POST /movies で送信値を確認する
#### フォームから送信したデータを受け取る
4.4 では、映画のタイトル・監督・公開年・ジャンル・紹介文を入力するフォームを作成した。
フォームには、送信先を指定する`action="/movies"`と、送信に使う HTTPメソッドを指定する`method="post"`がある。
送信ボタンを押すと、ブラウザは入力値を含む`POST /movies`リクエストを送る。

#### POST /moviesのルートを追加する
`app.rb`ファイルに、`POST /movies`を処理するルートを追加する。
このルートでは、送信された値を確認しやすい形にして、レスポンスとして返す。
ここで使うのが、Sinatra の`params`と、Ruby の`inspect`メソッドである。
- `params`：リクエストで送られたパラメーターを扱う。
- `params.inspect`：`params`の内容を、確認しやすい文字列にする。
- `content_type：text`：レスポンスの`Content-Type`をテキストに指定する。

#### GET /movies と POST /movies の違い
同じ`/movies`というパスでも、HTTPメソッドが異なれば、別のルートとして扱われる。
|ルート   |役割   |
|---|---|
|GET /movies   |映画一覧を表示する   |
|POST /movies   |フォームから送られた値を確認する   |

#### この段階では、映画はまだ保存されない
フォームから送信した値がレスポンスに表示されても、それだけで映画が保存されたことにはならない。
受け取った値をファイルやデータベースなどに保存する処理は、別途必要になる。
今回は、フォームから送られた値が Sinatara に届いていることを確認する段階である。

### 4.6 Networkパネルで Form Data を見る
#### フォーム送信時の通信を確認する
これまで、映画の登録フォームを作成し、Sinatara側で送信された値を確認する処理を用意した。
今回は、Chrome の DevTools にある Networkパネルを使い、フォーム送信時の HTTPリクエストとレスポンスを確認する。

#### Networkパネルで確認する項目
|確認する場所   |確認する内容   |
|---|---|
|Headers   |Request Method が POST になっている   |
|Headers   |Request URL のパスが /movies になっている  |
|Headers   |Status Code が 200 OK になっている   |
|Headers   |リクエストの Content-Type が application/x-www-form-urlencoded になっている   |
|Headers   |レスポンスの Content-Type が text/plain になっている   |
|Payload   |Form Data にフォームの入力値が含まれている   |
|Response   |params.inspect による確認用の文字列が返っている   |

#### HTML と送信データの関係
フォームの HTML に送信した属性は、実際の HTTPリクエストに反映される。
|HTML の記述   |通信で確認できること   |
|---|---|
|action="/movies"   |リクエスト先のパスが /movies になる   |
|method="post"   |Request Method が POST になる   |
|name="title"   |Form Data の項目名が title になる   |
|タイトル欄に入力した値   |Form Data の title に対応する値になる   |

#### 今回の学びのポイント
HTML に書いた action・method・name の指定が、実際の通信にどのように反映されるのかを確認した。
また、リクエストで送ったデータと、Sinatra が受け取ったパラメーター、ブラウザに返されるレスポンスを見比べることで、フォーム送信の一連の流れを確認できる。
なお、この段階では送信された映画情報は保存されない。
あくまでも、フォームから送った値が Sinatra に届いていることを確認するための処理である。

### 4.7 HTMLフォームが直接送れるメソッドは GET と POST
#### GET と POST の役割を整理する
HTMLフォームから HTTPリクエストを送信するとき、基本となるメソッドは GET と POST である。
今回の映画図鑑では、次のように使い分けている。
|操作   |HTTPメソッド   |役割   |
|---|---|---|
|映画登録画面を表示する   |GET   |登録フォームを取得する   |
|フォームの入力値を送信する   |POST   |入力した映画情報をサーバーへ送る   |

#### GET：情報を取得する
映画登録画面を表示するときは、`GET /movies/new`を使用する。
ブラウザからこのリクエストを受け取ると、Sinatra は対応するルートを実行し、`views/new.erb`を使って登録画面を返す。

#### POST：データを送信する
映画登録フォームには、次の指定がある。
- `action="/movies"`：送信先のパスを指定する。
- `method="post"`：送信に使用する HTTPメソッドを指定する。

送信ボタンを押すと、ブラウザは`POST /movies`を送信する。
Sinatra側では、`params`を使って送信された値を取得できる。
ただし、この段階では入力した映画情報は保存されない。
値を保存するには、サーバー側で保存処理を実装する必要がある。

#### 今回の学びのポイント
HTTPメソッドは、リクエストで何をしたいのかを表す。
今回の映画図鑑では、登録画面を表示するときは`GET`、フォームの入力値を送るときは`POST`を使用する。
また、POST でデータを送信しただけでは保存されない。
送信と保存は別の処理である。

### 4.8 この章のコードを確認する
#### 第4章で追加・変更したもの
第4章では、映画一覧ページから登録画面へ移動し、入力した映画情報をサーバーへ送信するための仕組みを作成した。
|追加・変更したもの   |役割   |
|---|---|
|GET /movies/new   |映画登録画面を表示する   |
|views/new.erb   |映画登録フォームの HTML を記述する   |
|POST /movies   |フォームから送信された値を一時的に確認する   |
|views/index.erb   |映画登録画面へのリンクを追加する   |
|public/stylesheets/application.css   |リンクやフォームの見た目を整える   |

#### app.rb の役割を振り返る
`app.rb`ファイルには、映画データと、HTTPリクエストに対応する処理を記述する。
今回の映画図鑑では、次のルートを使っている。
|ルート   |役割   |
|---|---|
|GET /   |/movies へ転送する   |
|GET /movies   |映画一覧を表示する   |
|GET /movies/new   |映画登録画面を表示する   |
|POST /movies   |フォームから送信された値を確認する   |

同じ`/movies`というパスでも、`GET`と`POST`では処理が異なる。
`GET /movies`は映画一覧を表示し、`POST /movies`は送信された入力値を確認する。
このように、HTTPメソッドとパスの組み合わせによって、実行する処理が決まる。

#### 映画登録フォームからデータを送信するまで
映画一覧ページのリンクをクリックすると、ブラウザは`GET /movies/new`を送信する。
Sinatra は対応するルートを実行し、`views/new.erb`を使って映画登録画面を返す。
登録画面で映画情報を入力して送信すると、フォームの`action`と`method`の指定に従い、`POST /movies`が送信される。
Sinatra では、`params`を使って入力値を取得できる。
`name`属性で指定した値が、`params`のキーになる。

### 第4章を通して学んだこと
Webアプリケーションでは、画面を表示する処理と、フォームからデータを受け取る処理を分けて考えることが大切である。
また、HTML のリンクやフォーム、Sinatra のルート、ERBテンプレート、CSS は、それぞれ異なる役割を持ちながら連携している。
それぞれの役割とつながりを意識することで、ブラウザの操作からサーバー側の処理まで、一連の流れとして捉えられるようになる。
