## 💡 本日の学び・気付き
### 5.1 受け取った値を、後から使えるように保存する
#### 第4章で実装した処理を振り返る
第4章では、映画登録フォームから送信された値を、Sinatra の`params`で受け取り、`params.inspect`を使って確認した。
しかし、この処理は受け取った値をレスポンスとして返すだけで、映画データを保存するものではない。

#### データを保存する必要性
アプリのメモリー上にあるデータは、アプリを再起動すると、そこで変更した内容が失われる。
そのため、登録した映画を次のリクエストやアプリの再起動後にも利用できるようにするには、データをファイルなどに保存する必要がある。

#### 今回の学びのポイント
第5章では、映画データを JSONファイルに保存する仕組みを作る。
フォームから値を受け取ることと、受け取った値を保存することは別の処理である。
まずは、この違いを理解することが今回の目的である。

#### そもそも JSON とは？
JSON は、**データを一定のルールに従って文字で表現するための形式**。
正式名称は*JavaScript Object Notation*（JavaScriptオブジェクト表記法）という。
読み方は「ジェイソン」。
プログラムで扱うデータを、ファイルに保存したり、別のプログラムに渡したりするときに使われる。
たとえば、映画のタイトルや監督名をデータとして扱う場合、次のように表現できる。
```json
{
  "title": "月面喫茶",
  "director": "山田アキラ",
  "year": "2042"
}
```
|JSON の記述   |意味   |
|---|---|
|"title"   |データの項目名   |
|"月面喫茶"   |タイトルの値   |
|"director"   |監督の項目名   |
|"山田アキラ"   |監督名の値   |
|"year"   |公開年の項目名   |
|"2042"   |公開年の値   |

このように、**どの項目に、どの値が入っているのかを分かりやすく表現する**ことができる。

#### なぜ JSON が必要なのか？
映画図鑑では、Ruby のハッシュを使い、次のように表現していた。
```ruby
{
  "title" => "月面喫茶",
  "director" => "山田アキラ",
  "year" => "2042"
}
```
Ruby の配列やハッシュを使えば、プログラムの中で映画データを扱うことができる。
しかし、アプリのメモリー上にあるデータは、アプリを再起動すると、そこで変更した内容が失われてしまう。
そこで、映画データをファイルに保存して、必要なときに読み込めるようにしたい。
そのために利用するのが**JSON**。

**Ruby の配列・ハッシュ**
プログラムの中でデータを扱う
　　　↓
**JSON形式の文字列に変換する**
保存できる形式にする
　　　↓
`data/movies.json`
映画データをファイルに保存する

#### Ruby のハッシュと JSON は何が違うのか？
**① Ruby のハッシュ**
Ruby のプログラム内で使うデータ
```ruby
{
  "title" => "月面喫茶",
  "director" => "山田アキラ"
}
```
Ruby のハッシュでは、今回のように`=>`を使ってキーと値を結び付けている。

**② JSON**
データを表現するための形式
```json
{
  "title": "月面喫茶",
  "director": "山田アキラ"
}
```
JSON では、キーと値の間に`:`を使う。

違いを整理すると、次のようになる。
|比較   |Ruby のハッシュ   |JSON   |
|---|---|---|
|主な用途   |Ruby でデータを扱う   |データを保存・交換するために表現する   |
|キーと値の区切り   |=> またはシンボルなど   |:   |
|データの例   |Ruby のハッシュオブジェクト   |JSON形式の文字列   |
