### 5.2 data/movies.json を作る
#### 映画データの保存先を用意する
第5章では、映画データを JSON形式のファイルに保存するため、`data/movies.json`を用意する。
これまで`app.rb`ファイルに記述していた映画データをファイルに移すことで、アプリの再起動後も登録したデータを読み込めるようにする。

#### data/ と public/ の違い
|ディレクトリ   |役割   |
|---|---|
|data/   |アプリケーションが読み書きするデータを保存する   |
|public/   |CSS や画像など、ブラウザから直接取得できる静的ファイルを置く   |

映画の保存データは、ブラウザから直接取得できる`public/`ではなく、`data/`に分けて管理する。

#### JSON形式で映画データを表現する
JSON では、キーとの間に`:`を使う。
Ruby のハッシュでは`=>`を使っていたが、JSON では記述方法が異なる。
また、今回の映画データは、複数の映画を配列としてまとめ、それぞれの映画をオブジェクトとして表現する。

#### 映画ごとに ID を付ける
映画データには、タイトルや監督などの情報に加えて、id を持たせる。
同じタイトルの映画が登録される可能性があるため、タイトルとは別に、それぞれの映画を区別できる ID が必要になる。
今回の教材では、UUID という形式の ID を使用する。

#### 作業の流れ
まず、プロジェクト内に保存用の`data/`ディレクトリを用意する。
ターミナルで、現在の作業を場所を確認する。
```zsh
pwd
```
続いて、次のコマンドを実行する。
```zsh
mkdir -p data
```
`-p`オプションは同じ名前のディレクトリが既に存在していても作成時のエラーを避けてくれる。

作成できたか、確認する。
```zsh
ls
```
続いて、映画データを保存する JSONファイルを作成する。
```zsh
vim data/movies.json
```
- `data/`：先ほど作成したディレクトリ。
- `movies.json`：これから作る JSONファイル。

あとは、FBC Press: Sinatra の指示にある内容を記述すれば OK。
保存するまでは、フィアルは実際に作成されない点に注意！
保存ができたらファイルの中身を確認し、JSON の書き方になっているかを確かめる。
```zsh
cat data/movies.json
```

#### 今回の学びのポイント
映画データを Ruby のプログラム内に直接記述するのではなく、JSONファイルに分けて保存することで、データを読み書きできるようにする。
また、保存先を`data/`に分けることや、映画ごとに ID を付けることにも、それぞれ理由がある。
これらの仕組みを理解しながら、データを保存する処理へ進んでいく。

### 5.3 JSON を読み込む
#### JSON を扱う準備
Ruby で　JSON形式のデータを扱うために、`require "json"`を追加した。
また、`MOVIES_FILE`という定数を定義し、`data/movies.json`のファイルパスを指定した。
`File.join`でパスを組み立て、`__dir__`を使うことで、`app.rb`ファイルの場所を基準に保存ファイルを指定できるようにした。

#### JSONファイルを読み込む
`load-movies`メソッドを追加し、JSONファイルから映画データを読み込む処理をまとめた。
`File.read`でファイルの内容を文字列として読み込み、`JSON.parse`で Ruby の配列やハッシュに変換する。

#### 映画一覧のデータ取得元を変更する
映画一覧のルートで、これまで`app.rb`ファイルに直接記述していた映画データではなく、`load_movies`で読み込んだデータを利用するように変更した。
これにより、映画データを JSONファイルで管理しながら、既存のテンプレートを使って一覧表示できるようになる。

### 5.4 UUID で ID を作る
#### require "securerandom"とは？
`require`は、プログラムで利用するライブラリを読み込むための記述。
今回の`securerandom`は、ランダムな値などを生成するための Ruby標準ライブラリ。
この章では、これを使って`UUID`を生成する。

#### SecureRandom.uuid とは？
`UUID`を生成するには、次のメソッドを使う。
```ruby
SecureRandom.uuid
```
たとえば、実行すると次のような文字列が生成される。
```text
c55c1d37-f3cf-469e-a746-a3044279c716
```
今のところ、`SecureRandom.uuid`を呼び出すと**映画を区別するための ID を生成できる**と押さえておけばよい。

#### なぜタイトルを ID に使わないのか？
もしタイトルをそのまま ID にすると、同じタイトルの映画を区別しにくくなってしまう。
一方、映画ごとに別の ID を付ければ、タイトルが同じでも、それぞれを区別できる。
|項目   |役割   |
|---|---|
|title   |映画のタイトルを表す   |
|id   |その映画を他の映画と区別する   |

今回、ID を付けるのは、**映画の内容を表すためではなく、個々の映画を識別するため**。

### 5.5 フォームの値を映画データにする
#### movie_params は何をするメソッド？
```ruby
def movie_params
  {
    "title" => params["title"].to_s,
    "director" => params["director"].to_s,
    "year" => params["year"].to_s,
    "genre" => params["genre"].to_s,
    "description" => params["description"].to_s
  }
end
```
コードを読んでみると、「**フォームから送信された5つの項目のそれぞれの値を1件分の映画のデータとして表すハッシュにまとめるためのメソッド**」だということが分かる。

たとえば、フォームから次の値が送信されたとする。
|項目   |送信された値   |
|---|---|
|title   |月面喫茶   |
|director   |山田アキラ   |
|year   |2042   |
|genre   |SF   |
|description   |月面にある小さな喫茶店を舞台にした物語   |

`movie_params`は、これらを次のような形にまとめる。
```ruby
{
  "title" => "月面喫茶",
  "director" => "山田アキラ",
  "year" => "2042",
  "genre" => "SF",
  "description" => "月面にある小さな喫茶店を舞台にした物語"
```
これで、5つの項目の値を一つのまとまりとして扱えるようになる。

#### なぜ、わざわざメソッドにまとめるの？
5つの値を毎回別々に取り出して扱うこともできる。
しかし、映画の登録処理を行うたびに、同じ取り出し処理を何度も書くと、コードが長くなり、管理もしにくくなってしまう。
そこで、`movie_params`にまとめておくことで、必要なときにそのメソッドを呼び出せるようにする。

また、`def movie_params ... end`の中で最後に評価されるのはハッシュ。
メソッドの最後の式の値が戻り値になる。
つまり、`movie_params`を呼び出すと、5項目をまとめたハッシュが返ってくるということ。

#### ここまでのまとめ
- `movie_params`：フォームから送信された5つの項目をハッシュにまとめる。
- `params["..."]`：`...`の入力値を取り出す。
- ハッシュにまとめただけでは、JSONファイルへの保存は行われない。

### 5.6 JSONファイルへ書き戻す
#### def save_movies(movies) は何を意味するのか？
括弧の中にある`movies`は、メソッドが受け取る引数。
呼び出すときに渡された映画データをこのメソッドの中で`movies`という名前で扱う。

#### JSON.generate(movies) は何をするのか？
Ruby の配列やハッシュを、JSON形式の文字列に変換する処理。
たとえば、Ruby のハッシュが次のようになっていたとする。
```ruby
{
  "title" => "月面喫茶",
  "director" => "山田アキラ"
}
```
`JSON.generate`によって、JSON形式の文字列に変換できる。
```json
{"title":"月面喫茶","director":"山田アキラ"}
```
Ruby のハッシュで使っていた`=>`が、JSON では`:`に変わっている。
*Ruby のデータを、そのままファイルに書くのではなく、JSON形式に変換してから書き込む**必要がある。

#### File.write は何をするのか？
```ruby
File.write(MOVIES_FILE, JSON.generate(movies))
```
`File.write`は、指定したファイルに文字列を書き込むためのメソッド。
今回の引数は 2つある。
|引数   |意味   |
|---|---|
|MOVIES_FILE   |書き込み先のファイルパス   |
|JSON.generate(movies)   |ファイルに書き込む JSON形式の文字列   |

つまり、この 1行は「映画データを JSON形式に変換し、`data/movies.json`に書き込む」という処理になる。

#### 処理の全体像
**Ruby の配列・ハッシュ**
映画データをプログラム内で扱う
　　　↓
`JSON.generate`
Ruby のデータを JSON形式の文字列に変換する
　　　↓
`File.write`
JSON形式の文字列をファイルに書き込む
　　　↓
`data/movies.json`
映画データをファイルに保存する
