### 6.3 ID で映画を探す
#### コードを理解する
この節で`app.rb`ファイルに新たに書いたコードは以下のとおり。
```ruby
def find_movie(id)
  load_movies.find { |movie| movie["id"] == id }
end
```
① `def find_movie(id)`
`find_movie`というメソッドを定義。
引数の`id`には、探したい映画の ID を受け取る。
たとえば、このような感じに。
```ruby
find_movie("ID002")
```

② `load_movies`
これは第5章で作ったメソッド。
```ruby
def load_movies
  JSON.parse(File.read(MOVIES_FILE))
end
```
JSONファイルから映画のデータを読み込み、Ruby の配列・ハッシュに変換して返す。
つまり、`find_movie`は、この`load_movies`を利用して映画の配列を取得している。

③ `.find { |movie| movie["id"] == id }`
`find`は、配列の中から条件に一致する最初の要素を返すメソッド。
たとえば、次のような配列があるとする。
```ruby
movies = [
  { "id" => "ID001", "title" => "月面喫茶" },
  { "id" => "ID002", "title" => "北風のリズム" },
  { "id" => "ID003", "title" => "週末ロケット" }
]
```
ここで、次の処理を考えてみる。
```ruby
movies.find { |movie| movie["id"] == "ID002" }
```
何をしているのか、順番に整理する。
|記述   |意味   |
|---|---|
|movies   |映画の配列   |
|.find   |条件に一致する要素を探す   |
|\|movie\|   |配列から取り出した1件の映画を受け取る変数   |
|movie["id"]   |その映画が持つ ID を取得する   |
|==   |左右の値が等しいか比較する   |
|"ID002"   |探したい ID   |

`find`は配列の要素を順番に調べる。
```text
月面喫茶
ID：ID001 => 不一致

北風のリズム
ID：ID002 => 一致

週末ロケット
ID：ID003 => 不一致

find の戻り値 => 北風のリズム
```

#### 条件に一致する映画がなかったら？
一致する映画がなければ、`find`メソッドは`nil`を返す。

### 6.4 詳細画面を表示する
#### 追加するコードの役割を確認する
```ruby
get "/movies/:id" do
  @movie = find_movie(params["id"])
  halt 404, "映画が見つかりません" if @movie.nil?

  erb :show
end
```
|処理   |役割   |
|---|---|
|get "/movies/:id"   |映画1件の詳細画面への GETリクエストを受け取る   |
|params["id"]   |URL から映画の ID を取得する   |
|find_movie(..)   |ID が一致する映画を探す   |
|@movie   |見つかった映画1件を保持する   |
|halt 404, ...   |映画が見つからなければ処理を止めて404を返す   |
|erb :show   |詳細画面のテンプレートを表示する   |

#### 今回のポイント
1. `find_movie(params["id"])`で指定された映画を探す。
2. `@movie`に映画1件分のデータを保持する。
3. 映画が見つからなければ`halt`で`404`を返す。
4. `erb :show`で詳細画面の HTML を作る。
5. `halt` = 処理を止めてレスポンスを返す。（読み方は、ホルト）

### 6.5 紹介文の改行は CSS で扱う
#### CSS のコードを理解する
```css
.movie-description {
  white-space: pre-line;
}
```
`white-space: pre-line`とは？
通常、HTML ではテキスト中の改行や連続した空白は、そのまま画面に遠泳されないことがある。
そこで、CSS の`white-space`プロパティを使う。
`pre-line`を指定すると、**テキスト中の改行を画面に反映しつつ、連続した空白は通常通り扱う**ようになる。

#### メディアクエリでスマートフォンに対応する
##### メディアクエリとは？
画面の幅など、特定の条件に応じて CSS の指定を切り替える仕組み。

#### 今回のポイント
1. HTML では改行がそのまま表示されないことがある。
2. CSS の`white-space: pre-line`で改行を反映できる。
3. メディアクエリで画面幅に応じたレイアウトに切り替えられる。

### 6.6 一覧から詳細へ移動する
#### 詳細リンクの仕組みを理解する
```erb
<a href="/movies/<%= h(movie["id"]) %>"
```
|記述   |意味   |
|---|---|
|/movies/   |映画詳細画面の URL の先頭部分   |
|movie["id"]   |現在のループで扱っている映画の ID   |
|h(...)   |HTML として安全に出力するためのエスケープ   |

たとえば、映画の ID が`abc-123`だった場合、生成されるリンク先は次のようになる。
```text
/movies/abc-123
```
この URL にアクセスすると、すでに`app.rb`に用意してある次のルートが処理する。
```ruby
get "/movies/:id" do
```
そして、`params["id"]`から URL に含まれる ID を受け取り、映画を探す。
これが、**すでに作成した詳細画面と一覧画面を繋ぐ作業**。

#### 裏側の処理
**① 一覧画面**
index.erb
`href="/movies/映画のID"`を持つリンクを生成する。

**② ブラウザ**
リンクをクリックして詳細 URL へアクセスする。

　　　↓

`find_movie`で該当する映画を探し、`show.erb`を表示する。

### 6.7 登録後は詳細画面へ移動する
#### コードの意味を理解する
```ruby
#{movie["id"]}
```
これは Ruby の文字列の中に変数や式の結果などを埋め込む構文。
たとえば、登録した映画の ID が`abc-123`だった場合、次の URL になる。
```text
/movies/abc-123
```
POST処理の中では、先に次のように映画を作成している。
```ruby
movie = { "id" => SecureRandom.uuid }.merge(movie_params)
```
この時点で、変数`movie`には新しく生成された ID が入っている。
そのため、最後のリダイレクト処理でも同じ ID を利用できる。

映画が見つからないため、レスポンスのステータスコードは`404`になる。

#### 処理の流れを整理する
**① 詳細画面の URL にアクセス**
例：`http://localhost:4567/movies/not-found`
　　　↓
**② URL から ID を取得**
`params["id"]`の値は`"not-found"`
　　　↓
**③ 映画を検索**
`find_movie`で該当する映画を探す。
　　　↓
**④ 映画が見つからない**
`@movie`が`nil`になる。
　　　↓
**404 映画が見つかりません**
`halt`によって処理を停止し、`404`を返す。

### 考えてみよう
- なぜ一覧画面にすべての属性を表示しないのでしょうか。
- `/movies` と `/movies/:id` は、どちらも映画に関係する URL ですが、何が違うのでしょうか。
- 存在しない ID に対して、なぜ通常の一覧画面ではなく 404 を返すのでしょうか。

#### ① なぜ一覧画面にすべての属性を表示しないのでしょうか？
**答え：一覧画面では映画を探しやすくし、詳しい情報は詳細画面で確認できるようにするため。**

#### ② /movies と /movies/:id は、どちらも映画に関係する URL ですが、何が違うのでしょうか。
**答え：/movies は映画の集合を表し、/movies/:id は特定の1件の映画を表す。**

#### ③ 存在しない ID に対して、なぜ通常の一覧画面ではなく 404 を返すのでしょうか。
**答え：利用者が指定した映画が存在しないことを正しい HTTPステータスコードで伝えるため。**
